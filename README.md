# 예술in 스프린트 기록

우아한테크코스 레벨4 스프린트마다 한 일과 이유, 진행도, 코치에게 요청할 것을 모아 두는 페이지다.
데모데이에는 이 페이지를 띄워 위에서부터 순서대로 발표한다. 빌드 없이 정적 파일만으로 동작한다.

주소: https://sprint.yesulin.art (Cloudflare `sprint` CNAME → Vercel 프로젝트 `yesulin-sprint-log`, DNS only)

## 내용 수정

화면 코드는 건드리지 않고 `data/`만 고친다. 빈 칸은 페이지에 작성 가이드로 보인다.

| 파일 | 내용 |
| --- | --- |
| `data/site.js` | 레벨4 전체에 한 번 적는 것: 방향 한 문장, 문서 링크, 지표 정의, 보일 기술 분야, 팀원 |
| `data/sprint-N.js` | 스프린트별 기록. 섹션 순서는 페이지 순서와 같다 |

- 여러 줄은 백틱(`` `...` ``)으로 감싸 적는다. 빈 줄은 문단, `- `로 시작하는 줄은 목록이 된다.
- `**굵게**`, `` `코드` ``, `[이름](https://...)`을 쓸 수 있다.
- 이미지는 `assets/` 아래에 넣고 경로를 적는다.
- 본문 시각화는 `visuals` 배열에 적는다. `kind`는 숫자 비교 `bars`, 구성 비교 `flow`, 날짜별 실행 기록 `timeline`을 지원한다. 핵심 작업·가설 사이클·유저 데이터·기술 요구사항의 추가 항목에 쓸 수 있다.
- `bars`의 `rows`에는 `label`·`value`를 적고, 미완료 집계는 `partial: true`로 구분한다. `flow`는 `columns`, `timeline`은 `days`를 사용한다. 실제 작성 예시는 `data/sprint-2.js`에 있다.
- 파일에 문법 오류가 있으면 페이지 위에 어느 파일 몇 번째 줄인지 표시된다.
- 이 페이지는 링크만 있으면 누구나 볼 수 있다. 개인 정보, 내부 IP·키 같은 값은 적지 않는다.

## 페이지 구성

개요(`index.html`)는 레벨4 방향, 팀, 스프린트 목록과 백로그 진행도를 보여 준다.
스프린트 페이지(`sprint.html?n=1`)는 데모데이 발표 순서를 따르고, 섹션을 상단 탭으로 나눠 보여 준다.

| 탭 | 섹션 |
| --- | --- |
| Overview | 1~4 |
| Product | 5 |
| Backend | 6 |
| Soft Skill | 7 |
| Retro & Coach | 8, 9 |

`data/site.js`의 `layout`을 비우면 예전처럼 한 페이지에 모든 섹션이 보인다. `#user-data`처럼 섹션 안의 주소로 들어오면 그 섹션이 든 탭이 열린다.

1. 한눈에 보기 — 핵심 작업 제목만 모은 목록. 누르면 해당 카드로 이동한다 (`highlights`)
2. 핵심 작업 — 작업별 담당·상태·내용·관련 PR (`highlights`)
3. 이번 스프린트 초점 — 공식 안내가 던진 질문에 대한 팀의 답 (`focus`)
4. 동작하는 제품 — 이번 스프린트에 실제로 달라진 부분 (`product`)
5. 가설과 결과 — 가설 사이클, 유저 데이터, 사용자 모집 활동 (`hypothesis`, `userData`, `recruiting`)
6. 기술 요구사항 — 이유·적용·대안·전후·알게 된 점, 완료 조건, 장애 1건 (`tech`)
7. 팀으로 일하는 방식 — 소프트스킬 활동 (`softskill`)
8. 회고와 다음 스프린트 — 회고, 백로그 진행, 다음 스프린트 (`retro`, `backlog`, `next`)
9. 코치에게 — 도움이 필요한 점, 공유하고 싶은 것 (`coach`)

`carryOver: true`로 두면 완료하지 못한 백로그가 다음 스프린트 아래에 우선순위별로 자동으로 모인다.
요구사항별 LMS+ 제출·승인 상태는 `submission.status`에 적으면 스프린트 페이지의 배지에 반영된다.

## 로컬에서 보기

`index.html`을 브라우저로 바로 열어도 된다. 로컬 서버로 볼 때는 다음을 실행한다.

```bash
python -m http.server 5417
```

## 배포

Vercel 프로젝트 `yesulin-sprint-log`가 이 저장소(`yesulIn-prototype/woowa-sprint`)와 연결되어 있다. 빌드 단계는 없다.

- `main`에 push하면 운영(https://sprint.yesulin.art)에 자동으로 배포된다.
- 다른 브랜치에 push하면 미리보기 주소가 만들어진다. 미리보기는 Vercel에 로그인해야 볼 수 있다.
- 급할 때는 이 폴더에서 CLI로 직접 배포할 수도 있다. 이때도 같은 변경을 `main`에 올려 저장소와 운영을 맞춘다.

```bash
vercel deploy --prod
```


## 제출용 누적 문서와 요약 보기

- `hypotheses.html`: 가설 검증 기록만 스프린트 순서로 누적한다.
- `user-report.html`: 유저 데이터 리포트만 스프린트 순서로 누적한다. 두 문서 모두 같은 `data/sprint-N.js`를 읽으므로 별도 복사하지 않는다.
- 스프린트별 `presentation.hideSections`로 필요한 섹션만 보일 수 있다. S2는 별도 회고·코치 섹션을 숨기고 소프트스킬 회고는 유지한다.
- 핵심 작업의 `summary`, 기술 요구사항의 `compact: true`와 추가 항목별 `summary`를 쓰면 결과를 먼저 보여 주고 상세 근거를 접는다. 그림은 본문에 그대로 표시한다.
- 지표 정의를 바꿀 때는 해당 스프린트에만 반영하고 이전 기록은 보존한다. 제안한 기준과 확정한 기준, 미집계와 0을 구분한다.

- S2 백엔드 요약은 `tech.backend.report`에서 편집한다. `runs`의 실제 시작·실패 요청 수로 전후 성공·실패 비율 그림을 직접 그린다. 다른 RPS의 실행을 최대 처리량이나 개선 배율로 표현하지 않는다.
- S2 제품 본문은 `hypothesis.concise`, `userData.report`를 사용한다. 10월 관측값을 먼저 보여 주고 8·9월 GA4 기록과 리텐션은 과거 참고 자료로 접어 둔다. 가설 7개 필드와 원자료는 누적 문서에 보존한다.
- S2의 `overview`는 핵심 결과 네 가지, 공고 전달 흐름, 다음 작업과 서비스 변경을 요약한다. 긴 작업 기록은 같은 페이지에서 펼쳐 볼 수 있다.
- `userData.report.compact`는 지표 설명을 짧게 보여 주고 집계 근거를 접는다. 요구사항의 `partial: true`는 △ 부분 충족으로 표시하며, 백엔드 작업의 `status`와 제출 승인 상태는 별도로 관리한다.
